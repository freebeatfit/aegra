## Status definitions

| Status | Meaning |
|:--|:--|
| **Supported** | Available in the current release and tested. |
| **Coming soon** | Actively being worked on or has a concrete plan. |
| **Not yet planned** | Not on the immediate roadmap. May be added based on demand. |

## Feature matrix

### Assistants and graphs

| Feature | Status | Notes |
|:--|:--|:--|
| Assistants CRUD | Supported | Create, read, update, delete, and search assistants. |
| Assistant versioning | Supported | Each update creates a new version. Pin or roll back. |
| Graph schemas | Supported | Input, output, state, and config schemas exposed via API. |
| Graph visualization | Supported | Mermaid graph structure returned by the API. |

### Threads and state

| Feature | Status | Notes |
|:--|:--|:--|
| Thread CRUD | Supported | Create, read, update, delete, and search threads. |
| State persistence | Supported | PostgreSQL checkpoints via LangGraph. |
| Thread state inspection | Supported | Get current state, values, and next nodes for any thread. |
| Thread history | Supported | Full checkpoint history with replay capability. |

### Runs and execution

| Feature | Status | Notes |
|:--|:--|:--|
| Background runs | Supported | Non-blocking execution with polling. |
| Streaming (Agent Protocol v2) | Supported | Thread-scoped SSE on `POST /threads/{thread_id}/stream/events` with channels `values`, `updates`, `messages`, `tools`, `lifecycle`, `input`, `checkpoints`, `tasks`, `custom`. |
| v1 run streams | Removed (fork) | `runs/stream` and `GET .../runs/{run_id}/stream` answer `410 Gone`; see [FB_PATCHES.md](https://github.com/freebeatfit/aegra/blob/fb/0.11.0/FB_PATCHES.md). |
| SSE reconnection | Supported | A reconnect replays each namespace's latest state, then the events after it, within `RESUMABLE_STREAM_TTL_SECONDS`. |
| Sync wait | Supported | Block until run completes and return final output. |
| Subgraph streaming | Supported | Subgraph events arrive with their namespace; filter with `namespaces` / `depth`. |
| Stateless runs | Supported | Execute without persisting thread state. |
| Multitask strategy `reject` | Supported | A run with `multitask_strategy: "reject"` (v2 `multitaskStrategy`) is refused while the thread has a pending or running run: `409` on REST, `unknown_error` on v2 `run.start`. `interrupt`, `rollback` and `enqueue` are accepted but not applied yet; the new run starts alongside the active one. |
| Checkpoint durability | Supported | `durability` (`sync`, `async`, `exit`) per run or cron, deprecated `checkpoint_during` alias, server default via `checkpointer.durability` or `AEGRA_CHECKPOINT_DURABILITY`. |
| Cron / scheduled jobs | Supported | Create, read, update, delete, search, and count scheduled jobs, including metadata filtering. Standard and seconds-level cron expressions. IANA timezone support. |

### No-op request fields

The LangGraph SDK sends these run and cron fields on every call. Every run streams on Agent Protocol v2, so they change nothing: Aegra accepts only the values below and answers any other value with `422`, naming the field.

| Field | Accepted | Why it is a no-op |
|:--|:--|:--|
| `stream_mode` | omitted, `"values"`, `["values"]` | The SDK default. Channels are chosen per connection on `POST /threads/{thread_id}/stream/events`. |
| `stream_subgraphs` | omitted, `false` | The SDK default. Subgraph events reach the thread stream; filter them with `namespaces` / `depth`. |
| `stream_resumable` | omitted, `false` | The SDK default. Every thread stream is resumable. |
| `on_disconnect` | omitted, `"continue"` | REST runs never stream, so a disconnect never cancels them. |
| `stream` | omitted, `false` | Not sent by the SDK; kept so an old body still validates. |

### Scaling and reliability

| Feature | Status | Notes |
|:--|:--|:--|
| Worker job queue | Supported | Redis BLPOP with configurable worker count and concurrency. |
| Concurrent execution | Supported | Up to `N_JOBS_PER_WORKER` (default 10) concurrent runs per worker. |
| Lease-based crash recovery | Supported | Automatic re-execution of runs from crashed workers via checkpoint resumption. |
| Cross-instance cancel | Supported | Cancel propagates via Redis pub/sub to any instance. |
| Bulk cancel | Supported | `POST /runs/cancel` by status or by thread and run ids; SDK `cancel_many`. |
| Cancel with `action=rollback` | Coming soon | Both cancel routes accept `interrupt` and `cancel`; `rollback` (cancel, then delete the run and its checkpoints) returns `422` until it lands. |
| Job timeout | Supported | Configurable max execution time (default 1 hour). |
| Postgres fallback | Supported | Workers fall back to DB polling when Redis is unavailable. |
| Multi-instance SSE | Supported | One Redis Stream per thread, read with `XREAD BLOCK`, so any instance serves any thread's stream. |

### Human-in-the-loop

| Feature | Status | Notes |
|:--|:--|:--|
| Interrupt before / after | Supported | Pause execution at specific nodes. |
| User approval gates | Supported | Resume or reject interrupted runs. |
| State editing | Supported | Modify thread state before resuming. |
| Answer pending interrupts only | Supported | `input.respond` to an interrupt that is not pending on the thread answers `no_such_interrupt`. While a run is in flight the check is skipped, as on the LangGraph server. Of two concurrent answers to one interrupt only the first resumes. |
| Resume with `update` / `goto` | Supported | `input.respond` folds a state update or directed jump into the resume, one checkpoint. Also available as `command` on v1 run creation. |
